# Invoice export: implementation plan

**Goal:** Add `tally export --format json|csv` and fix the split rounding bug.

**Architecture:** A pure formatter module (`src/export.ts`) used by a new CLI subcommand. No new dependencies.

**Tech Stack:** TypeScript run directly by Node 22 (type stripping), `node:test`.

**Spec:** `docs/superpowers/specs/2026-11-03-export-design.md`

## Global Constraints
- No new dependencies. Imports use `.ts` extensions.
- Run the suite with `npm test`.

### Task 1: export formatters
**Files:** create `src/export.ts`, create `test/export.test.ts`.
**Interfaces:** `toJson(store: Store, taxRate: number): string`, `toCsv(store: Store, taxRate: number): string`.
- `toJson` returns `JSON.stringify` of `[{ id, customer, totalCents }]` in store order, `customer` being the customer's name.
- `toCsv` returns the header `id,customer,total` and one row per invoice; quote fields containing `,` or `"` (double inner quotes); `total` via `formatCents`.
- Tests: `toJson` on a two-invoice store; `toCsv` header and a quoted name.
**Verify:** `npm test` passes.

### Task 2: `export` subcommand
**Files:** modify `src/cli.ts`, create `test/cli.test.ts`.
- `node src/cli.ts export --format <fmt> <file>`: json/csv write the formatter output to stdout, exit 0.
- Any other or missing format: stderr `unknown format: <value>`, exit 2, nothing on stdout.
- Tests: spawn the CLI with `--format json`, `--format csv` and `--format xml` against `examples/invoices.json`; assert exit codes.
**Verify:** `npm test` passes.

### Task 3: split rounding fix
**Files:** modify `src/money.ts`, modify `test/billing.test.ts`.
- RED first: `split(1000, 3)` must equal `[334, 333, 333]`; add a sum-preservation test for a few totals.
- Then fix `split`.
**Verify:** `npm test` passes.
